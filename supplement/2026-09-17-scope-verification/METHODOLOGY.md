# What this verification establishes

The historical benchmark runs, reference labels and original promise results stay frozen. These experiments answer two separate questions.

## Conditional detection mechanisms

For every retained “could detect” obligation, the catalog names the proposed check, the source of each input, when the rule applies, and when an omission can be decided. Fixtures supply hypothetical inputs through the real SDK recording path and run the existing registered AAP-2 predicate. They include compliant actions, the cited kind of failure, and insufficient evidence. Additional controls test incorrect bindings, late approval, failed prerequisite reads, incomplete recording and altered displayed output.

The fixtures establish that the declared mechanism can distinguish these controlled cases. They do not establish that the added inputs existed in the old traces, that users would have supplied them, or that modified benchmark agents would achieve the same behavior. No new model runs or LLM labels are generated.

The policy-to-check mapping remains a reviewed interpretation. Code makes that interpretation inspectable and repeats its application; it does not make the interpretation objective. A missing approval is a violation only when the recording contract establishes that approvals were completely recorded. Missing evidence otherwise stays unresolved. An omitted required action is evaluated only at a declared task-end boundary. Source metadata assumes a faithful controller; it is not proof of human identity.

Each undetected run is counted once. If at least one retained cited obligation has a supported mechanism, the run is conditionally checkable. If a previously conditional obligation lacks sufficient support and none of the run's other obligations qualifies, the run remains unresolved. Existing outside-scope assignments are preserved. We do not promote runs merely because a generic fixture exists.

## Initial-destination policy sensitivity

The AgentDojo experiments compare named allowlist definitions on the identical full corpus. Initial destination data come from native structured fields before injection. Neither attacker goals, labels nor post-action state grant permission. Each newly admitted destination has field-level provenance. The experiment repeats SDK evaluation and preserves every original witness, so lost detections and removed benign alarms can both be counted.

An initial address is a known destination, not permission to perform any operation or send any content there. A policy restricting agents to known destinations cannot detect all misuse of those destinations. Conversely, a legitimate task can authorize a new destination. These are limits of the declared restriction, distinct from errors in extracting its initial list.

No-injection runs are a separate reference group, not guaranteed policy-correct runs. Wrong destination arguments, simulator effects and ambiguous task scope are reported separately. Failed attacks are not labeled no violation simply because the specified attacker objective failed.

## Comparison with rerunning modified agents

A new model run would test live integration and agent behavior, but the model might take a different path and avoid the original violation. Controlled replay keeps the relevant violation fixed and tests whether the added records make it checkable. It is stronger for that narrow mechanism question and weaker for end-to-end deployment claims. A full benchmark rerun is not needed to report conditional checkability, provided that distinction is explicit.
