## Interface coordination

`ActionRecord.metadata` is optional and absent from legacy serialization.
`Session.guard` and `Session.record` accept keyword `action_id`, `event_id`, and `metadata`.
`Session.record_authorization` records a decision for one explicit invocation and hashes its arguments in Python.
Native integrations use AAP-1 with `authorization_mode="invocation"`. Broader native permission scope is retained
as evidence; applying it again requires an observed policy decision for the new invocation.
`checkpointTrace(sessionId, recordCount, prefixHash)` is separate from final `commitTrace`.

The edits share these interfaces; core owns SDK/commons/store/verifier/contract, each integration owns its
adapter and pinned upstream patch, and the run scripts own deployment state and evidence capture.
No task changes benchmark cohort membership or reinterprets the locked evaluation.
